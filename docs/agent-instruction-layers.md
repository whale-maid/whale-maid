## 0 一句话

三层注入链＝**全局（人）→ 工作区（机器与项目索引）→ 项目（这个项目怎么干）**。
每层**只说"这一层不做就会错的事"**，其余一律外挂 + 留指针。
⚠ 而 **`notes/` 与 `docs/`（讨论·日志）不是真源、仅供参考** —— 见 §5。

## 1 三层分工

| 层 | 文件 | 管什么 | ⛔ 不该放什么 |
|---|---|---|---|
| **L0-a 用户全局** | `~/.dsh/AGENTS.md` | **人格**（`PERSONA_LOAD`）· 跨机器跨项目的**主人偏好与边界**（称呼、放权、口吻、输入方式、汇报口径） | 具体项目细节 · 单机事实（端口 / 路径 / 版本） |
| **L0-b 工作区** | `work space/AGENTS.md` | **机器事实 ＋ 项目索引**（"有什么"）· 工作区操作规范（文档 / 回收站 / 派活 / 版本控制 / 模型调度） | 各项目的运行细节（端口 / 脚本 / 坑 → 项目层） |
| **L0-c 项目** | `<项目>/AGENTS.md` | **该项目怎么干**：定位 · 运行规范 · ＃坑 · 边界 · 入口指针 | 别的项目的事 · 历史叙述（→ `recon/` 或 `notes/`） |

- **注入顺序**：从宽泛到具体（全局 → 工作区根 → 项目根 → **更深子目录按需触发**）；内容冲突时**具体层优先** ✓
- **重复即错**：同一件事只在**一层**写正文，其他层只留指针 —— ⛔「**两份必然漂移**」✓
- **`AGENTS.local.md` / `CLAUDE.md`**：前者是叠加 overlay、后者是**同义候选**（内容与 `AGENTS.md` 相同则只渲染一次）✓

## 2 自指代（文件在文内怎么称呼自己与别人）

- **自称**：写「**本文件**」「**本目录**」「**本项目**」——⛔ 别写绝对路径（换机器/换盘就断）✗
- **指上层**：相对路径 ＋ 层名，如「工作区 `AGENTS.md` §⑤」「`../AGENTS.md` ②」✓
- **指下层**：写**项目名 ＋ 具体位置**（`phone-bridge/AGENTS.md`），⛔ 不写"某个项目的文档里"✗
- **跨层引用只引"判据"，不复制正文**：例如「按『L0 只放不说就会做错的』判」✓ 复制正文＝埋第二份真源 ✗
- **L1 指针义务**：「不知道它存在就找不到」的东西，项目 `AGENTS.md` **必须有一行指路**（放错＝埋了）✓
- **占位符约定**：路径写 `$DSH_HOME` / `work space` / 项目名，机器相关的写"（本机：…）"✓

## 3 维护规程（什么时候动哪一层）

| 事件 | 动哪一层 |
|---|---|
| 主人的偏好 / 边界 / 称呼口径变了 | **L0-a 全局** |
| 新建 / 移动 / 删除项目、端口与工具变动 | **L0-b 工作区**（同步根 `README.md` 索引） |
| 项目架构 / 配置 / 运行方式变了 | **该项目** `AGENTS.md` ＋ 它的 `docs/`（**同一次提交** ✓） |
| 只是"这次该查没查"的教训 | 就近写 `tools/docs/` 或项目 `docs/` —— **别往常驻层塞** ✗ |

- **进 L0 的唯一正当理由**：*agent 能不能自己发现？能就删* ✗（不是"这条重要"）
- **常驻层默认应当单调变短**；新增一条时优先想"能不能换成一行指针" ✓
- **同步义务**：改代码 / 配置 / 文档 ⇒ 同一次提交里更新对应文档（不攒）✓
- **注入层的代价**：L0 每个字符都在**每一轮**计价 ⇒ 长文档一律放 L2/`docs/`（不注入）✓

## 4 添设规程（新东西往哪放）

| 要放的东西 | 落点 |
|---|---|
| **新项目** | 先落 `AGENTS.md`（短）＋ `README.md`（可稍后）⇒ **再写码**（立项先文档）；登记进工作区 §索引 与根 `README.md` |
| 跨项目 / 未立项的设想、讨论 | `docs/discussions/YYYY-MM-DD-<slug>.md` |
| **有归属项目**的设想 | 该项目 `notes/YYYY-MM-DD-<slug>.md` ＋ 项目 `AGENTS.md` 一行指针 |
| 机制正文 / 现状结构 / "为什么这么做" | 该项目 `docs/`（每篇头部 `> 状态: current｜draft｜deprecated ｜ 更新: YYYY-MM-DD`，只信 `current`） |
| 历史快照 / 事故复盘 / 协议逆向 | `tools/recon/`（**只追加不覆盖**） |
| 主人在板上批的东西 | 鲸板评论 / 页面（真源 `board.json`）＋ 该项目的 `notes/` 摘要 |

巡检与检索：`node tools\docs-check.mjs`（一致性）· `node tools\docs-find.mjs <词>`（跨 L0/L1/L2/L3 **＋鲸板页**）✓

**技能（skill）与指针**（2026-10-09 补；技能 = **按需装载**的凝练文档，投递机制与 AGENTS 的"自动注入"不同，故单列）：

- **发现根**（读 `@deepseek-ai/dsh-skill-filesystem` 源码）：用户根 `~/.dsh/skills` ＋「会话 cwd 往上第一个含 `.git` 的目录」下的 `.dsh/skills`、`.agents/skills`
  ⇒ **项目子目录里的 `.dsh/skills` 不会被自动发现**（除非会话本身就开在那个项目上）。
- **放法**：跨工作区通用 → `~/.dsh/skills/`；本工作区跨项目 → `<工作区根>/.dsh/skills/`；**单项目别做成技能** → 直接写项目 `AGENTS.md`（项目内自动注入）或 `docs/`。
- **指针放哪**（判据＝"那一刻一定会被注入"的那份文件）：通用 → **用户级 `~/.dsh/AGENTS.md`**；工作区跨项目 → 工作区级 `AGENTS.md`；单项目 → **该项目 `AGENTS.md`**。
  ⛔ 不要把项目专属的指针再抄进工作区级 `AGENTS.md`（重复必然漂移）；工作区级只留项目清单。
- frontmatter 是 **YAML**：`description` 里出现未加引号的 `: `（冒号+空格）会让条目被**静默丢弃**
  （实测：`touhou_little_maid` 长期未被收录，改名无效，去掉那个冒号才收录）✓

## 5 ⭐ 真源判据（2026-10-08 主人补：`notes/` 与 `discussions/` **不是真源**）

**真源只有三处**：
1. **跨会话事实** → `~/.dsh/memory/facts.jsonl`（＋人读 `notes.md` / 热区 `index.md`）
2. **代码 / 配置 / 数据本身**（项目目录里跑着的那些）
3. **明确标了"真源"的文件**：鲸板 `board/board.json` · 看板 `~/.dsh/dsh-taskboard.json` 等

⚠ **`notes/` 与 `docs/`（讨论·日志）是"当时的思考快照"，仅供参考**：
会过时、会被后来的决定推翻、会与真源不一致 ✗

⇒ **用法四条**：
- 引用它们时标明**出处与日期**（如「`dsh-whale-board/notes/…`（2026-10-08）」）✓
- 引用前**核对真源**（代码 / 数据 / 记忆）——**冲突一律以真源为准** ✓
- 发现过期就在那份文档里补一行「**已被 X 取代（YYYY-MM-DD）**」，别让它悄悄变成第二份真源 ✗
- **禁止**把 `notes/` / `discussions/` 的内容当"已定事实"去执行（要执行先落记忆或写进 `AGENTS.md`/`docs/`）✓
