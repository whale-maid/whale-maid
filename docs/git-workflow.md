## 二、提交纪律

1. **`git status` 必须干净、或能一句话解释** ✓ —— 脏项攒多了这个命令就**失去信号价值** ✗（2026-10-09 前一度常驻 33 项 ✓，靠它挑文件反而出错 ✗）。
2. **一事一提交；提交按「事」不按目录** ✗ —— ⚠ **血例**：2026-10-09 妾身用 `git add preplan/` 把主人亲笔 `一份主人亲笔的草稿` 里未提交的改动**顺手提进了一版** ✗（内容没动，但以后**点名单个文件** ✓）。
3. **身份**：主人的提交 = `xiaocong <xiaocong@localhost>`（仓库默认 ✓）；**妾身的提交显式带**
   `-c user.name=whale-maid -c user.email=340211855+whale-maid@users.noreply.github.com` ✓（审计可分辨 ✓，且**不改**仓库默认 ✓）。
   ⚠ **邮箱必须是这个 noreply 地址**（`<账号id>+<用户名>@users.noreply.github.com`）：GitHub 的贡献格按**提交邮箱**归属，
   用任意本地邮箱（如 `whale@local`）提交**不会计入贡献图** ✗ —— 2026-10-10 实测踩到，已用 `filter-branch` 改写两个公开仓的历史 + 强推修正 ✓。
4. **动之前先提交**（留回退点 ✓）；**大二进制不进历史** ✗；**收班前清账一次** ✓。
5. 提交信息用**中文、说清「做了什么」**（2026-10-09 那四版就是样子 ✓）。
